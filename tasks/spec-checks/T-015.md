# Spec check T-015 (R-062)

## Verdict: `rework`

The design holds up. Reasons on `CommandError`, kinds taken from `reason.as_str()`, a generated
list with a currency test, empty group modules, `Parts`, and `NoTools` as the default all fit
the code on `main`. The dependents mostly assume exactly this mechanism. As written, though, the
spec cannot reach a green gate inside its `touches`:

- The one new `xtask/generated.toml` entry turns three iteration-0 tests red: a T-005 acceptance
  test, a second T-005 acceptance test and an xtask unit test.
- Replacing the kinds table turns a T-004 acceptance test red.
- The fixes for these, and the CHARTER text the ADR asks for, are in the hands of T-013, which
  is `in_progress`. So `depends_on: []` / "ready to dispatch" is wrong.

Each fix needs a director ruling written as a diff (METHODOLOGY §2.1). I also recommend a split
(finding 28). Together that is a re-spec, not a list of text edits, so the verdict is
`rework`. Every finding below gives the edit to make.

Checked against code: `crates/kiln-commands/src/{lib,registry,doc,buffer}.rs`,
`crates/kiln-control/src/lib.rs`, `apps/kiln-cli/src/main.rs`, `crates/kiln-workspace/src/*`,
`xtask/src/{policy,queue,precheck,gate,testbins}.rs`, `xtask/{generated,ledger,layers}.toml`,
`docs/control-protocol.md`, and every `acceptance_t00*` / `guard_t00*` file. Dependents read:
T-007, T-008, T-010, T-018, T-019, T-020, T-024, T-027, T-030, plus the touches and refusal
lines of T-021, T-022, T-023, T-025, T-026, T-031.

What is fine (VERIFIED):
- Every refusal site the spec lists exists and maps cleanly. They are doc.rs:167, 177, 247,
  316, 378, 434 and 483; buffer.rs:68; registry.rs:124–126 (`no_such_doc`); and the two
  `Internal` sites at registry.rs:379–381 and 435–440, plus the panic at
  kiln-control/src/lib.rs:137–145.
- `CommandError` derives `Serialize` with `tag = "code"` (registry.rs:219–221), so adding
  `reason` to `to_json` takes no code.
- `kiln-cli exec` prints `command_error_json` (main.rs:246, 255), not `to_json`, so CLI bytes
  are unaffected.
- No test outside `touches` constructs `CommandError::Rejected { message }` or calls
  `CommandError::rejected(..)`. They only use `{ .. }` patterns or `to_json()["code"]`.
- `guard_t006.rs` (kiln-commands, lines 71–91) checks exact message text only. T-015 keeps the
  messages, so this guard is **not** broken.
- AC-1 can be built with public API (`MemoryFs::set_fail_writes`, memory.rs:37; directory →

- The root `Cargo.toml` change touches only `[workspace.dependencies]`, so it is not a gate path
  (precheck.rs:94–121). `Cargo.lock` changes only path packages, so no `dependency versions`
  wording is needed (queue.rs:401–427).
- The tier is right (finding 29).

## 5. Size, tier, budget

**28. note (recommendation) — split into two tasks.** The spec bundles six deliverables:

1. a §3 contract change at about 12 sites;
2. a rewrite of the `kiln-control` kind derivation;
3. a renderer bin, a generated file, two currency tests and a `generated.toml` entry;
