## 3. The security boundary (spec question 3)

**10. blocker — no criterion catches lexical resolution or string-prefix comparison.**

These are the two classic wrong ways to confine. An implementation that does either passes
AC-1…AC-8 as written. VERIFIED in a scratch dir:
- *Lexical `..`.* With `root/s -> ../outside/d` and `root/t -> s/../secret.txt`, lexical
  normalisation gives `root/secret.txt` (inside). The kernel reads `work/outside/secret.txt`.
  An implementation that normalises link targets lexically and then opens through the kernel
  reads outside.
- *String prefix.* With a sibling `work/rootx/secret.txt` and `root/px -> ../rootx/secret.txt`,
  `realpath(px).startswith(realpath(root))` is `True`, while a component-wise check says
  outside.

Three more paths are not pinned:
- precedence `OutsideRoot` over `NotAFile` (AC-8 checks only over `NotFound`);
- a non-regular file outside, which an open-before-check implementation would block on;
- an outside device.

*Add to AC-1 (T-008:173–177),* fixtures `work/outside/d/` (a directory) and
`work/rootx/secret.txt`, and links `s -> ../outside/d`, `t -> s/../secret.txt` and
`px -> ../rootx/secret.txt`. `read` of `t` and `px` → `OutsideRoot`; `write_atomic` of each
→ `OutsideRoot`, with the snapshot unchanged.

*Add to AC-8 (T-008:222–226):*
- `up -> ..` → `read` `OutsideRoot` (not `NotAFile`);
- `self -> .` → `read` `NotAFile`;
- `po -> ../outside/fifo` (a FIFO made outside) → `read` `OutsideRoot` within 5 seconds;
- `dn -> /dev/null` → `read` and `is_file` give `OutsideRoot`/false.

**12. ambiguity — the location definition has gaps.**

T-008:50–53 defines a location only when every non-final component resolves. Three cases are
not covered:
- a missing or non-directory non-final component (`nodir/x`, `f.txt/x`; today `NotFound`,
  `disk.rs`:96–104);
- a missing component after the walk has already left the root (`dlink/missing/x`,
  `outlink -> ../outside/none` with request `outlink/x`);
- a failure such as `EACCES` while resolving outside the root.

"An absolute one as is" does not say whether the absolute target's own components are
followed. They must be, and finding 10 depends on it.

*Replace T-008:50–53 with:*

> **Location of a path `p`.** The entry reached by resolving `<root>/p` one component at a time
> as the kernel does: every symlink in any component is followed, and `..` inside a link target
> is applied to the directory actually reached so far (physically, never by lexical
> normalisation). A relative target is resolved against the link's directory. An absolute
> target is resolved from `/` in the same way. If a component does not exist or is not a
> directory before the last one, the location is the part resolved so far plus the remaining
> components.

*And add after T-008:92:*

> Once resolution has passed outside the root and does not come back, any failure to resolve
> further (missing entry, permission, not a directory) is `OutsideRoot`. Inside the root, a
> missing or non-directory component is `NotFound`, as today.

**13. ambiguity — checking the type and then opening can still hang.**

T-008:82 ("returned without blocking; the entry is not opened") and T-008:271–272 ("how a
non-regular file is detected without opening it") lead to stat, then open. A FIFO swapped in
between the two calls blocks the session forever.

D-3 (T-008:279–280) accepts that a change during one call "can slip through". A hang is a
different consequence, and `docs/protocol/paths.md`'s list of limits (T-008:115–117) does not
mention it.

One fix is to open with `O_NONBLOCK` and re-check the type with `File::metadata()`. Std has no
named `O_NONBLOCK` constant, so the implementer would have to hard-code it per `target_os`
through `OpenOptionsExt::custom_flags` (no new crate).

*Edit, choose one:*
- add to T-008:117 "…can slip through, and a FIFO swapped in during that window can make the
  request block (accepted, D-3)";
- or add to the Interface: "`read` opens the file non-blocking and refuses it as `NotAFile` if
  the opened entry is not a regular file".

The first is cheaper and consistent with D-3.

*Replace "`MemoryFs` is unchanged (it has no symlinks or special files)" (T-008:77–78) with:*
