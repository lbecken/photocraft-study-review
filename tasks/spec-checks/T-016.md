every worked example reproduce exactly in this environment. The dependencies build here with
the installed C compiler, add no UI/GPU crate, and change no locked version. The 44 `.rs` files

## 1. Implementable inside `touches`; breakage of existing tests

**1. blocker — `no-skip` aborts on the corpus, and can fail on valid corpus files too.**

`no-skip` scans every `.rs` file under `crates`, `apps` and `xtask`. Only `xtask/fixtures` is
excluded (noskip.rs:471–473, 503–508). Each file is parsed with `syn::parse_file(..)?`
(noskip.rs:354–355), so one file that does not parse aborts the step. Every
`corpus/rust-invalid/*.rs` file fails to parse by design. A valid corpus file containing
`#[ignore]`, `#[cfg_attr(…, ignore)]`, a `cfg`-gated test module or an `ignore` doc fence is a
finding.

Both are VERIFIED on a workspace copy with a corpus directory:
- `crates/kiln-testkit/corpus/rust-invalid/fn_paren.rs` containing `fn (` gives
  `xtask: parse …/fn_paren.rs: cannot parse string into token stream`;
- `corpus/rust/attrs.rs` containing `#[test] #[ignore] fn t() {}` gives
  `FAIL no-skip: 1 skip problems`.

Excluding the corpus in `noskip.rs` would be a gate-path change in `xtask/src`, which T-013
(`in_progress`, touches `xtask/src`) holds.

*Edit, preferred (no gate path):* in Pinned (b), store every corpus file as
`<name>.rs.txt`: `corpus/rust/*.rs.txt`, `corpus/rust-gaps/*.rs.txt`,
`corpus/rust-invalid/*.rs.txt`. Add: "No corpus file has the extension `.rs`. The gate's
`no-skip` step parses every `.rs` file under `crates/` (noskip.rs:471, 503)." Change the
glob wording in AC-1…AC-6 and the test names accordingly. rustc needs `--crate-name` for such
names; see finding 3.

*Alternative:* `depends_on: [T-013]` and add `xtask/src/noskip.rs  # GATE PATH: EXCLUDED +=
"crates/kiln-testkit/corpus"` to `touches`. That makes the task's approval need `gate paths`
and serialises it behind T-013. I advise against it.

**2. blocker — AC-4 contradicts `update`'s `Unchanged` rule.**

AC-4 draws edits of "0–20 chars" (T-016:163), so an insert of 0 chars, a delete of 0 chars, or
a replace by the same text leaves the text equal. The interface then requires `Unchanged`
(T-016:71). AC-4 requires "`Incremental` whenever the new tree has no error" (T-016:166). A test
written to AC-4 fails against a correct implementation. My generator, with the same
distribution, produced 228 no-op edits out of 6,800 (3.4%; 34 files × 200 edits).

The sentence also leaves open which tree is "the new tree". It could be the incremental tree
or `parse(new)`. The two can differ only when the incremental tree has an error.

*Edit (AC-4, last two sentences):* "The mode is `Unchanged` iff `new` equals the text before the
edit. Otherwise it is `Incremental` whenever `SyntaxTree::parse(new).has_error()` is false; when
the fresh tree has an error it may be `Incremental` or `Full`." Keep the interface rule
(T-016:73–75: `Full` only when the incremental tree has an error), and add: "a test can only
see the fresh tree; the spike found no edit on which the incremental tree had an error and the
fresh one did not (0 of 6,572)".

Evidence that this is implementable: on the 6,572 edits that changed the text (29 workspace sources and 5 invalid snippets, the same edit
alphabet), the incremental tree differed from the fresh one 4 times. All 4 times the
incremental tree had an error. It never differed while error-free, and the two never disagreed
on `has_error`.

**3. ambiguity — AC-1's compile oracle: the rustc command, its side effects, and "marked".**

The spec gives `rustc --edition 2024 --crate-type lib --emit metadata` (T-016:108). Run in a
test, whose cwd is `crates/kiln-syntax/`, rustc writes `lib<name>.rmeta` into that directory.
VERIFIED: `libmy_file.rmeta` and `libok_file.rmeta` appeared. These are untracked files. The
queue refuses a task worktree that is not clean, and "clean" includes untracked files
(queue.rs:5–7; git.rs:63, `status --porcelain --untracked-files=all`).

With the `.rs.txt` names of finding 1, rustc also fails on the crate name: `invalid character
'.' in crate name: foo.rs` (VERIFIED). "The one marked test" (T-016:152–153) names a mechanism
that does not exist. `no-skip` forbids `#[ignore]`, and there is no env-gating convention.

On the question of a definition of "compiles" that needs no spawned compiler: as written there
is none. AC-1 spawns rustc on every gate run. That is a spawned external tool in a test, which
CHARTER §3 decision 4 and AGENTS rule 3 otherwise route through a trait with a recorded fake.
The test tree does have precedent: T-024 has "exactly one marked test per tool".

*Edit, option A (recommended, no spawn in the gate):*

- Define: "`compiles` := the test author ran, and the reviewer re-runs once and records,
  `rustc +1.97.0 --edition 2024 --crate-type lib --emit metadata --crate-name corpus
  --cap-lints allow --out-dir <tmp> <file>` with exit 0 (`invalid`: exit ≠ 0)."
- In the gate, `corpus_is_pinned_and_compiles` checks the byte pins and that `syn::parse_file`
  succeeds on every `valid`/`gap` file and fails on every `invalid` file (finding 9).
- This turns "compiles" into "the exact bytes rustc accepted" and spawns nothing.

*Edit, option B (keep the spawn):* pin the full argv as above, including `--out-dir` = a fresh
temp directory removed afterwards and `--crate-name corpus`. Pin the program: `rustc` from
`PATH`, resolved by rustup through `rust-toolchain.toml`, which it finds from the crate
directory. Replace "marked" with "`corpus_is_pinned_and_compiles` is the only test in the
workspace that spawns `rustc`; it is not ignored or gated". Keep the 60 s timeout per file.

**4. ambiguity — crate-private accessors are dead code, and T-020/T-023 cannot add them.**

"Sibling modules use crate-private accessors that you design" (T-016:84–85). Until T-020 lands,
nothing in the library uses them, and `dead_code` fires. VERIFIED: a `pub` struct with an
unread field already warns in `kiln-search`. Under `clippy --all-targets -D warnings`
(gate.rs:39–47) the gate goes red. One implementer will delete them; another will add
`#[allow]`.

If T-016 does not provide what highlight and outline need, T-020 and T-023 are stuck. Neither
has `crates/kiln-syntax/src/tree.rs` or `lib.rs` in `touches` (T-020:10–15, T-023:10–14).

*Edit (Interface, after T-016:85):* pin them:
```rust
impl SyntaxTree {
    #[allow(dead_code)] // used by highlight (T-020) and outline (T-023)
    pub(crate) fn root(&self) -> tree_sitter::Node<'_>;
    #[allow(dead_code)] // byte offset in `text()` → char offset
    pub(crate) fn char_at_byte(&self, byte: usize) -> usize;
}
```
Use `allow`, not `expect`: T-020/T-023 cannot remove an `expect` because the file is outside
their `touches`. These two suffice for T-020's leaf/field rules and T-023's field walks.

**5. ambiguity — what `parse` does when tree-sitter returns no tree.**

The signature is infallible (T-016:70), but `Parser::set_language` returns `Result`
(ABI mismatch) and `Parser::parse` returns `Option<Tree>`. The workspace denies
`unwrap_used`, `expect_used` and `panic` (Cargo.toml lints). One implementer will add
`#[allow(clippy::expect_used)]`; another will build an internal "no tree" state. The two
choices give different `sexp`/`errors`.

*Edit (Interface):* "If tree-sitter yields no tree (it cannot with no timeout or cancellation
set, and a unit test proves `set_language` succeeds for the pinned grammar), `SyntaxTree` holds
no tree. Then `has_error() == true`, `errors() == [Error 0..len_chars]`,
`sexp() == "(ERROR@0..<len_chars>)"` and `node_count() == 1`. No lint is allowed for this."

**10. ambiguity — quoting inside `(MISSING "…")`.**

*Edit (T-016:93–94):* "Inside the quotes, `\` and `"` are written as `\\` and `\"`; no other

**14. ambiguity — `SyntaxTree`'s own trait impls.**

T-015 creates `#[derive(Debug, Default)] pub(crate) struct SyntaxState {}` (T-015:96), and
T-020 stores per-document trees in it (T-020:46–48). So `SyntaxTree: Debug` is required.
`tree_sitter::Parser` implements neither `Debug` nor `Clone` (VERIFIED in tree-sitter 0.27.1

keeps a `Parser` does not compile.

*Edit (Interface):* "`SyntaxTree: Clone + Debug + Send`. It keeps no `Parser`; one is made per
`parse`/`update`. `Debug` prints the char length and `has_error`, not the text."

## 5. Oracles, failability, observability

**20. note — each AC's oracle, and whether it can fail.**

- AC-2 is VERIFIED green today: 44 files, 17,362 lines, 0 error nodes, `syn` 0 failures. Every

**21. note — AC-2 is a permanent tripwire for every later task.** Any later `.rs` under

**22. note — measured cost of the ACs.**
- In a debug build: 1 MB of `(` parses in 0.53 s, 1 MB of `{` in 1.10 s, 10,000 nested `(` in
  5 ms. 10,000 nested balanced parens give 0 errors and depth about 10,000.
- 1 MB of lossily decoded random bytes parses in 8.4 s (240,032 error nodes).
- A 50 MB file (repeated `queue.rs`) parses in 17.2 s, with 16 M nodes.
- AC-4: 6,800 edits took 29.5 s in release, including two sexp renders per edit. In the
  gate's debug build, expect a few minutes (INFERRED). Budget the test step.

**23. note — stack safety is the implementation's job.** tree-sitter's parse does not
overflow. A recursive `sexp`/`errors`/`node_count` would overflow on deep valid nesting.
*Edit (Pinned (e)):* "tree walks use `TreeCursor` iteratively; no recursion over the tree".
`node_count` can be `root.descendant_count()`.
