# T-065 A desktop window that shows the Kiln UI

> **Spec check required.** Written (R-238) before T-056 merged. When T-056 has merged, a planner
> checks this spec against main: the frame function T-056 names ("Shared with T-065" in

## Goal
After this task `kiln [--root <dir>] [<path>…]` opens a desktop window on X11 that shows the
same UI `kiln script` runs (the shell of T-055 and the editor view of T-056) and is used with the
real keyboard and pointer. Where no window can be opened, `kiln` exits 2 with one line on stderr,
without a panic. With `--script <file>` the window takes its input from a script, so that the
reviewer and the evaluator can observe a real window under Xvfb (ADR-0008, Q-2 A). This is the
first desktop application: open a file, edit, undo, save.

Tier high: a dependency change (eframe and its window-system crates). No gate path. The approval
row needs the words **`dependency versions`** only if adding eframe changes the version of a
package already in main's lock (none did at main `197617c`, E-a; re-measured at the spec check);
it needs no `gate paths`. Independent test author (high tier).

Reading list: `docs/adr/0008-ui-observation.md` (decision 6, probe (d), rulings Q-2);
`tasks/T-056-editor-view.md` and `tasks/T-055-ui-script-observation.md` as merged;
`docs/protocol/ui.md`, `docs/protocol/ui-editor.md`; `docs/control-protocol.md` (`kiln-cli`
conventions for usage errors and a bad root).

## Interface

### Command line
- `kiln [--root <dir>] [--script <file>] [<path>…]`
  - Options before or after the paths, each at most once. The first argument `script` always
    names the subcommand `kiln script` (a file called `script` is opened through `Path` and
    `Open`).
  - Opens the window over the root (default: the current directory) on X11, with an inner size
    of 1280×800 points (the `kiln script` default), then opens each `<path>` in order exactly as
    `kiln script`'s start paths (T-056: as if typed into `Path` and opened), then draws the
    first frame. The UI is the one `kiln script` draws (T-056, "Shared with T-065"), with the
    same theme and style (dark theme, no caret blink).
  - Without `--script` the window runs until the user closes it; exit 0. Closing saves nothing
    and asks nothing (unsaved changes are lost; a prompt is later work).
  - Usage error (unknown option, an option twice or without its value, `--log`, `--memory` or
    `--size` given without `script`): exit 2, a message and the usage on stderr, nothing on
    stdout. Bad root: exit 2, nothing on stdout, a stderr message naming the root as given (as
    `kiln-cli`). `--script` file unreadable: exit 2, nothing on stdout.
  - **No window:** if the window system cannot be started — no display, a display that cannot
    be reached, or a display that is present but whose window system cannot start (a library
    missing, Q-7 A) — `kiln` exits **2** with nothing on stdout and exactly one stderr line, which
    does not contain `panicked`.
- `--script <file>`: the window takes its input from the script and closes after the last line.
  Script lines, response lines and exit codes are those of `kiln script` (0 every response
  `ok:true`, 3 at least one `ok:false`, 1 writing stdout failed, 2 as above), except that the
  window runs in real time: the `frames` and `settled` values of action responses and the
  `frames` total of a snapshot may differ from `kiln script`'s. Every other part of every
  response line, the snapshot's `root` included, is what `kiln script` prints for the same
  script, root and paths. Responses are written on stdout after the window has closed; stderr
  is separate. Input from the window system while a script runs is not specified (under Xvfb
  there is none). For the reviewer and the evaluator where a display exists; not run by the gate.
- `kiln --help`, `kiln -h`, `kiln script --help`: usage on stdout (window and script forms),
  exit 0.

### Rust API used by tests
None. All criteria are tested through the built `kiln` binary; no test needs `kiln_control::Host`
(it stays available as in T-055).

## Pinned
- (a) Errors: no new refusal kind, no new registry command, no new UI request kind. Exit codes as
  in Interface; every start failure is exit 2.
- (b) Files: the window reads `--script` once, whole, at start, and writes no file of its own;
  documents are saved only by `doc.save` (ADR-0008 decision 5). The GL driver may write its own
  cache: measured, Mesa wrote `$HOME/.cache/mesa_shader_cache/…` under Xvfb, and nothing with
  `MESA_SHADER_CACHE_DISABLE=true` (E-d). `kiln script` loads no GL driver.
- (c) Order of checks: usage → `--script` readable → root → window system → start paths in
  order → first frame.
- (d) Linux, X11 only (no Wayland). `eframe` `=0.37.0` with `default-features = false` and
  features `default_fonts`, `glow`, `x11`, in `[workspace.dependencies]` and
  `crates/kiln-ui/Cargo.toml` (not in `apps/kiln/Cargo.toml`: the window is started through
  `kiln-ui`). Built here (E-a); `accesskit` and the default features fail on `wayland-sys`
  (E-c). Fonts built in. Window inner size 1280×800 points; under `xvfb-run -s "-screen 0
  1280x800x24"` the toolkit reported pixels-per-point 1 and a content rectangle of 1280×800, also
  on a 1600×1000 screen (E-b).
- (e) Threat model: the window adds no file access of its own beyond the GL driver's cache ((b));
  the files it reads and writes are those of commands, confined to the root
  (`docs/protocol/paths.md`). Kiln spawns no process; the only connection it opens is the one to
  the display server named by `DISPLAY`. A document's text is drawn, never interpreted.
- (f) Tests that pin what this changes: `apps/kiln/tests/guard_t055.rs` asserts only a non-zero
  status, empty stdout and a message for bare `kiln` without a display (T-055 w4): exit 2 keeps
  it true, so it is not in `touches`. The T-055 and T-056 tests stay in the gate and must pass
  with eframe linked (at main `197617c` the T-055 binary tests passed with it: 26, 2, 9; E-a).
  `docs/protocol/ui.md` lines 24–25 ("`kiln` with no subcommand still only says … exits 1") are
  replaced. `docs/development.md:33` ("desktop placeholder (exits 1: UI not built)") becomes false;
  T-064 corrects it (not in `touches`). Not to be pinned: the usage text, message texts (the
  winit error text names a path on the build machine), the layout.
- (g) Worked examples (the probe of R-237, E-b; a scratch function that ran T-055's shell with
  `eframe::run_ui_native`):
  - no `DISPLAY`/`WAYLAND_DISPLAY`: `run_native` returned `Err` (`winit EventLoopError: os
    error …`), no panic; `DISPLAY=:99` with nothing listening: the same;
  - Xvfb without the two libraries: panic `Library libxkbcommon-x11.so could not be loaded.`
    inside winit's `EventLoop::new`, exit 101 (so Q-7 A needs the implementer to catch it);
  - Xvfb with the libraries: exit 0 in 0.61 s and 0.25 s; with an egui plugin's `output_hook`
    building `kiln script`'s observation from the frame's accessibility update and shapes, the
    window's root equalled `kiln script`'s for the same state (`equal: True`, 14 nodes).
- (h) Evaluator call for `ui.window` (ADR-0008 (O1)–(O5), Q-2 A): by the recipe below, `kiln
  --root d a.rs src/b.rs --script s.jsonl` with typing, a click `at`, a scroll and snapshots,
  compared with `kiln script s.jsonl --root d a.rs src/b.rs` (AC-2); the item is confirmed only if
  the real window started and AC-2 held in the evaluator's run; otherwise `not_evaluated`.
- (i) Sentences for `docs/protocol/ui.md`, worded for copying, with evidence:
  - E6 "`kiln` opens a window on X11 (not Wayland). If the window system cannot be started it
    exits 2 with one line on stderr and nothing on stdout." Evidence: AC-1, AC-3; E-b.
  - "`kiln --script <file>` runs a script in the window: its output is that of `kiln script`
    except the frame counts." Evidence: AC-2.
  - Limits, copied: "Under Xvfb the window needs the libraries `libxkbcommon-x11` and
    `libxcb-xkb`; the GL driver may write its shader cache under the home directory." (E-b, E-d.)

### Recipe for the reviewer and the evaluator (nothing installed on the system)
```sh
D=<scratch>/xlibs; mkdir -p "$D/debs" && (cd "$D/debs" && apt-get download libxkbcommon-x11-0 libxcb-xkb1) && for f in "$D"/debs/*.deb; do dpkg-deb -x "$f" "$D/root"; done
env -u WAYLAND_DISPLAY LD_LIBRARY_PATH="$D/root/usr/lib/x86_64-linux-gnu" MESA_SHADER_CACHE_DISABLE=true timeout 120 xvfb-run -a -s "-screen 0 1280x800x24" sh -c 'exec target/debug/kiln --root d src/a.rs --script s.jsonl 2>stderr.txt' > stdout.txt; echo "exit=$?"
```
`xvfb-run` on this machine runs the command as `"$@" 2>&1` (`/usr/bin/xvfb-run` line 184), so
stderr is redirected inside the wrapped command. For Q-7's check, the same without
`LD_LIBRARY_PATH`.

## Acceptance criteria
Through the built `kiln` binary, every process under a timeout. On base (main after T-056) bare
`kiln` prints that the window is not built and exits 1, so every criterion fails there.
- AC-1 (`ui.window`, start; gate): with `DISPLAY`, `WAYLAND_DISPLAY` and `WAYLAND_SOCKET` removed:
  `kiln --root d src/a.rs` exits 2, stdout empty, stderr exactly one line that does not contain
  `panicked`; `kiln --root <missing>` exits 2 and its stderr names `<missing>` (the root is
  checked before the window system); `kiln --bogus`, `kiln --root d --root d` and `kiln --log
  l.jsonl` exit 2 with empty stdout; `kiln --root d --script missing.jsonl` exits 2; `kiln
  --help` exits 0 with the usage on stdout. Oracle: exit codes, empty stdout, the root's name.
- AC-2 (`ui.window`, real window; run by the reviewer in round 1 and by the evaluator, **not by
  the gate**: no display exists where the gate runs, ADR-0008 d, Q-2 A): by the recipe, `kiln
  --root d a.rs src/b.rs missing.rs --script s.jsonl` (a script with snapshots, typing into
  `Editor`, a click `at`, a `scroll`, `ctrl+S`) exits with the code `kiln script` gives and prints
  the same lines as `kiln script s.jsonl --root d a.rs src/b.rs missing.rs`, with the action
  results' `frames`, `settled` and the snapshot's `frames` taken out; its first snapshot shows
  `Title` beginning with `src/b.rs` and `Message` beginning with `not_found`; the files on disk
  afterwards equal those of the headless run on a copy. Oracle: equality with headless; the files.
- AC-3 (Q-7 A; reviewer, not the gate): under Xvfb without the two libraries, `kiln --root d
  src/a.rs` exits 2, stdout empty, stderr one line without `panicked`. Oracle: exit code, stderr.
