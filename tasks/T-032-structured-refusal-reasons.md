# T-032 Structured refusal reasons; kinds from reasons; kinds generated from code

## Goal
`CommandError::Rejected` carries only a message, so `kiln-control` derives the protocol `kind`
by matching message text (`rejected_kind`), and a reworded message silently becomes `other`.
After this task:
- every refusal and internal error carries a structured reason set where it is raised;
- `kiln-control` reports `kind = reason.as_str()` without reading any message;
- the set of `rejected` and `internal` kinds, each with its description, is **generated from
  code** into `docs/commands.json` (`"error_kinds"`, printed by `kiln-cli commands --schema`).
  The gate's existing `schema` step already checks that file byte for byte, so a stale list
  fails the gate.

A task that adds a kind adds one reason variant with its description and regenerates
`docs/commands.json`. It never edits a hand-written list. The eleven kinds of the iteration-1
feature tasks are added here, so those tasks only raise them.

This was part (d) of the former T-030. It moved to T-015 in R-060 and was split out again by the
director in D-041, from spec check R-062 (`tasks/spec-checks/T-015.md`), whose blockers 1–5 are
resolved in "Resolutions" below. ADR-0004 must be accepted before `ready`. No gate path: no
`xtask/` file changes (resolution of blockers 1–2). This task does not edit `docs/CHARTER.md`:
once ADR-0004 is accepted, the director publishes its CHARTER §3 decision 2 sentence as a
separate low-tier task (D-042).

Reading list: CHARTER §3 decision 2; ADR-0002; ADR-0004; `tasks/spec-checks/T-015.md`;
`crates/kiln-commands/src/{registry,doc,buffer}.rs` (refusal sites doc.rs:167, 177, 247, 316,

## Interface

### Reasons (`crates/kiln-commands/src/reason.rs`, re-exported from the crate root)
```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum RejectReason {
    InvalidPath, NoSuchDocument, UnsavedChanges, NotFound, NotAFile, IoError, DecodeError,
    OutOfRange, InvertedRange, Other,
    InvalidPattern, StalePreview, NoSuchPreview, ToolUnavailable, ToolNotFound, ToolTimeout,
    ToolFailed, NoRecording, FormatError, ChangedOnDisk, InvalidKeymap,
}
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum InternalReason { Panic, ResultSchema, Other }   // declaration order = today's table order
impl RejectReason   { pub const ALL: &'static [RejectReason];   pub fn as_str(self) -> &'static str; pub fn description(self) -> &'static str; }
impl InternalReason { pub const ALL: &'static [InternalReason]; pub fn as_str(self) -> &'static str; pub fn description(self) -> &'static str; }

impl From<&kiln_workspace::VfsError>  for RejectReason { … }   // NotFound, NotAFile, IoError
impl From<&kiln_workspace::OpenError> for RejectReason { … }   // Vfs(e) → From<&VfsError>; Decode → DecodeError
impl From<&kiln_text::EditError>      for RejectReason { … }   // OutOfBounds → OutOfRange; InvertedRange → InvertedRange
impl From<&kiln_workspace::ToolError> for RejectReason { … }   // Unavailable, NotFound, Timeout, Failed, NoRecording → Tool*/NoRecording
```
- `ALL` lists the variants in declaration order, and `as_str()` equals the serde form.
- Every `From` is an exhaustive `match` with **no catch-all arm**. A variant added to a
  lower-layer enum later (T-008's `VfsError::OutsideRoot`) then does not compile until it is
  mapped here.
- Errors that only one command group raises are mapped in that group's own module (T-021's
  `QueryError`, T-031's keymap errors). `reason.rs` holds only the shared mappings.
- Descriptions of today's kinds are today's "When" cells word for word, except `invalid_path`,
  which becomes "the path is not a valid root-relative path (see Paths in
  `docs/control-protocol.md`)". The new kinds' descriptions:

| Variant | Kind | Description | Raised by |
|---|---|---|---|
| `InvalidPattern` | `invalid_pattern` | the search pattern is empty or is not a valid regular expression | T-021, T-022, T-023 |
| `StalePreview` | `stale_preview` | a file of a replace preview changed or was removed since the preview | T-022 |
| `NoSuchPreview` | `no_such_preview` | no stored replace preview has this id | T-022 |
| `ToolUnavailable` | `tool_unavailable` | external tools are off for this session (the default) | T-024, T-026 |
| `ToolNotFound` | `tool_not_found` | the external tool's program was not found | T-024, T-026 |
| `ToolTimeout` | `tool_timeout` | the external tool ran longer than its limit and was stopped | T-024, T-026 |
| `ToolFailed` | `tool_failed` | the external tool failed or gave no usable result | T-024 |
| `NoRecording` | `no_recording` | the replayed tool recording has no output for this request | T-024, T-026 |
| `FormatError` | `format_error` | rustfmt could not format the text | T-026 |
| `ChangedOnDisk` | `changed_on_disk` | the file changed or was removed on disk since it was read | T-027 |
| `InvalidKeymap` | `invalid_keymap` | the keymap file or chord is not valid | T-031 |

Not added here: `OutsideRoot` (T-008) and `NotABoundary` (T-010), each with its mapping, in
this file. Reason variants may exist before any command raises them (ADR-0004).

### `CommandError` (registry.rs)
```rust
pub enum CommandError {                     // derives unchanged
    UnknownCommand { message: String },                          // unchanged
    InvalidParams { message: String, details: Vec<String> },     // unchanged
    Rejected { reason: RejectReason, message: String },          // CHANGED
    Internal { reason: InternalReason, message: String },        // CHANGED
}
impl CommandError {
    pub fn rejected(reason: RejectReason, message: impl Into<String>) -> Self;  // CHANGED: reason required
    pub fn to_json(&self) -> serde_json::Value;   // + "reason" for rejected/internal only
}
```
`Display` is unchanged, and so is every message. Today's sources map like this:
- `RelPath::new` failure → `InvalidPath`;
- no open document → `NoSuchDocument` (also the refusal of T-015's `Docs::get`);
- a dirty `doc.close` → `UnsavedChanges`;
- VFS, open and edit errors → their `From` mapping;
- result schema → `Internal{ResultSchema}`; does not serialize → `Internal{Other}`;
- a panic in the host → `Internal{Panic}`.

### Kinds and the generated list
- `kiln-control`: `kind` of `rejected`/`internal` = `reason.as_str()`. **No message text is
  consulted** for any code or kind. `rejected_kind` and the path tracking used only by it are
  removed. The crate docs (lib.rs:14–21) say kinds come from reasons, and that the full list is
  `error_kinds` in `docs/commands.json` plus the request-level rows of
  `docs/control-protocol.md`. The protocol error object does not carry `reason`.
- An `Internal { reason: Panic, .. }` is reported with message `` command `<name>` panicked ``,
  whatever its own message; the host constructs it with `PANICKED` as today.
- `Registry::describe()` gains a top-level key (its other keys are unchanged):
  `"error_kinds": {"rejected": [{"kind": "...", "when": "..."}, …], "internal": [{"kind": ..., "when": ...}, …]}`,
  with each list in `ALL` order. `docs/commands.json` is regenerated with
  `cargo xtask schema --write`. `kiln-cli commands --schema` prints it, as it prints
  `describe()` today.
- `docs/control-protocol.md`, "Error codes and kinds". The table stays exactly as it is: all 23
  rows, including the 10 `rejected` and 3 `internal` rows. Only these sentences change:
  - the sentence starting "The `kind` of a `rejected` error is currently derived …" becomes:
    "The `kind` of a `rejected` or `internal` error comes from a structured reason set where the
    error is raised; no message text is consulted.";
  - the sentence "This table is the specified set of `(code, kind)` pairs; no other pair is
    produced." becomes: "The request-level rows of this table (codes `invalid_json`,
    `invalid_request`, `unknown_command`, `invalid_params`) and the `rejected`/`internal` kinds
    in `error_kinds` of `docs/commands.json` (`kiln-cli commands --schema`, generated from code)
    are the specified set; no other pair is produced. The `rejected` and `internal` rows above
    are the kinds of iteration 0; kinds added since are listed only in `error_kinds`. Where a
    row's 'When' text differs from `error_kinds`, `error_kinds` governs; later tasks do not edit
    table cells.";
  - nothing else in the file changes.
- The CHARTER §3 decision 2 sentence of ADR-0004 is published by the director, not by this
  task (D-042: a separate low-tier task once ADR-0004 is accepted).

## Acceptance criteria
- AC-1 (reasons at their sources): through `standard_registry().execute`, each refusal gives
  exactly its reason:
  - `doc.open "../x"`; `doc.text {"doc":9}`; a dirty `doc.close`;
  - `doc.open` of a missing file, of a directory (`MemoryFs` with `d/x`, open `d`), and of
    `b"\xff"`;
  - `doc.insert` at 99; `doc.delete` 2..1; `buffer.insert` at 99;
  - `doc.save` with `set_fail_writes(true)` → `IoError`.

  `to_json()["reason"] == as_str()`. This fails on base by assertion. Oracle: exact value.
- AC-2 (kinds from reasons only, control protocol): for every `RejectReason` `r`,
  `kiln_control::command_error_json` of `rejected(r, m)` has `code: "rejected"`,
  `kind: r.as_str()`. This holds for `m = "zz unrelated"` and for the worked example's
  message. The same holds for every `InternalReason`. Oracle: exact value.
- AC-3 (generated list): `kiln-cli commands --schema` has `error_kinds.rejected` and
  `error_kinds.internal` equal to `ALL` (kinds) with descriptions. Every `rejected`/`internal`
  row of the table in `docs/control-protocol.md` is in it with the same kind, and it contains
  `invalid_path`, `no_such_document`, `unsaved_changes`, `not_found`, `not_a_file`,
  `decode_error`, `out_of_range`, `inverted_range` (rejected) and `panic`, `result_schema`,
  `other` (internal). The committed
  `docs/commands.json` equals the dump; the gate's `schema` step checks this, and the test
  re-checks it. Oracle: exact value.
- AC-4 (protocol bytes unchanged, a **guard**): `apps/kiln-cli/tests/guard_t032_cli.rs` runs the
  worked example of `docs/control-protocol.md` and a ≥ 300-request fixed-seed session (paths
  from `[a-z0-9/._]`, never containing `: ` and never naming a directory; ids at most 64
  characters) through `kiln-cli run` on a temporary root. The output equals constants recorded
  on base and embedded in the file. `kiln-cli commands` output is not compared. Oracle:
  differential.
- AC-5 (`From` mappings): each variant of `VfsError`, `OpenError`, `EditError` and `ToolError`
  maps to the pinned reason. Oracle: exact value (the reviewer checks the absence of catch-all
  arms by reading).
- AC-6 (panic kind): a panic is `internal`/`panic` with message `` command `<name>` panicked ``
  via `InternalReason::Panic`. Here this is checked by reading; T-029's fuzz self-test exercises
  it later.
- AC-7 (documents): the two replaced sentences and their replacement text are exact, and the
  reviewer checks the `git diff` of `docs/control-protocol.md`.
