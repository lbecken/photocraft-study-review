# T-012 Publish the iteration-0 evaluation and the scorecard it changes

## Goal
The independent evaluation of iteration 0 (run R-050, `main` at `d3978db`) becomes part of
`main`, and `docs/scorecard.md` shows the items it confirmed as `verified`.

## Why this is a task
An evaluation file is a ledger path, but committing it changes what `cargo xtask scorecard`
derives, so the generated `docs/scorecard.md` goes stale and the gate turns red. The generated
file is not a ledger path and may reach `main` only through the queue. So the evaluation and the
regenerated scorecard travel together on a task branch. (Director-written spec: the change is
mechanical and has no implementation choices; recorded as decision D-034.)

## Acceptance criteria
- AC-1: `evaluations/iter-0.md` on the branch is byte-identical to the evaluator's final file.
- AC-2: `docs/scorecard.md` is regenerated by `cargo xtask scorecard` and the gate is green.
- AC-3: no other path changes.

## Out of scope
Any change to items, tests or code. Defects the evaluator filed are separate tasks (T-010, T-011).
