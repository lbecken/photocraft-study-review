# T-056 A window that shows and edits one document by dispatching commands only

## Goal
After this task `kiln [--root <dir>] [<path>…]` opens a desktop window. It shows the shell of
T-055 and an **editor view** of the current document: its text with syntax colours, a caret and
selection, and scrolling. Typing, deleting, Enter, caret movement, undo, redo and save work from
the keyboard and the pointer, and each is a registry command dispatched through the session
(ADR-0008 decision 5). The same UI runs headless in `kiln script`, where tests and the evaluator
observe it. This is the first usable application: open a file, edit, undo, save.

No gate path. Independent test author (high tier). The approval row needs no `gate paths`; it
needs `dependency versions` only if a version already in main's lock changes (none did at
R-225's resolution, ADR-0008 c2).

Reading list: `docs/adr/0008-ui-observation.md`; `tasks/T-055-*.md` and `docs/protocol/ui.md` as
merged; `docs/protocol/cursor.md` (selection, `cursor.move`, `cursor.set`), `docs/protocol/syntax.md`
(`syntax.highlight` kinds), `docs/protocol/eol.md`, `docs/control-protocol.md` (`doc.*`);
`docs/commands.json` (params and refusals of the commands named below).

## Interface

### Command line
- `kiln [--root <dir>] [<path>…] [--script <file>]`: opens the window over the root (default:
  the current directory) and opens each `<path>` as `doc.open` would, in order; a refused path
  shows its kind in `Message` (T-055) and the window still opens.
- No display: if no window can be opened (no display, or the window system refuses), `kiln`
  exits **2** with nothing on stdout and one stderr line, without a panic. A bad root: exit 2 as
  `kiln-cli` refuses it.
- `--script <file>`: the window takes its input from the script instead of the user (same lines
  and responses as `kiln script`, written to stdout) and closes after the last line; the exit
  code is that of `kiln script`. For the reviewer and the evaluator where a display exists
  (ADR-0008 d); not run by the gate.
- `kiln script` (T-055) runs the same UI and accepts the same `[<path>…]` after its script
  argument, opened at start as above.

### The current document
The editor view shows one document, the **current document**: the one most recently opened by a
successful `doc.open` from any source (the UI, a script's control request, the command line);
if it is closed, the open document with the highest id; with none open, no editor view is shown.

### What the UI shows (nodes, for `kiln script` snapshots)
- A node labelled `Title` whose value begins with the current document's path and contains the
  word `modified` exactly when `doc.info` reports it dirty (no `Title` node with no document).
- A node with role `multiline_text_input`, labelled `Editor`: `value` is the document's text;
  `selection` is its selection (anchor and head in chars, as `cursor.get` reports); `rows` are
  the painted rows: one row per document line in view, top to bottom, its runs' texts together
  equal to the visible part of that line without its line break; no wrapping (a long line is cut
  at the view's right edge).
- Colours: each run's colour is the colour of the `syntax.highlight` kind of its chars, from this
  table (for a document whose path ends in `.rs`; every other document, and a `.rs` document
  `syntax.highlight` refuses as `too_large`, is painted in the `plain` colour):

  | kind | colour |
  |---|---|
  | `plain` | `#dcdcdc` |
  | `keyword` | `#569cd6` |
  | `type` | `#4ec9b0` |
  | `function` | `#dcdcaa` |
  | `string` | `#ce9178` |
  | `number` | `#b5cea8` |
  | `comment` | `#6a9955` |

  A selection does not change text colours.
- The shell of T-055 (`Path`, `Open`, `Documents`, `Message`) stays.

### Input (in the window and in scripts)
With the editor focused (a click into it focuses it):
| Input | Dispatches | Effect |
|---|---|---|
| typed text | `doc.replace` of the selection, or `doc.insert` at the caret when the selection is empty | the text replaces the selection; the caret follows it |
| `Enter` | as typed text, with the document's line ending (`doc.info` `line_ending`) | a CRLF document stays CRLF |
| `Backspace` | `doc.delete` | deletes the selection, or with an empty selection the range from where `cursor.move {by:"char", forward:false}` would put the head to the caret (a CRLF goes whole); nothing at offset 0 |
| `Delete` | `doc.delete` | the selection, or the range from the caret to where `cursor.move {by:"char", forward:true}` would put the head; nothing at the end |
| `ArrowLeft` / `ArrowRight` | `cursor.move {by:"char"}` | `ctrl` + arrow: `by:"word"`; `shift`: `extend:true` |
| `ArrowUp` / `ArrowDown` | `cursor.move {by:"line"}` | `shift`: `extend:true` |
| `Home` / `End` | `cursor.set` | head to the start / end of its line (`doc.line`); `shift` keeps the anchor |
| pointer click at a char | `cursor.set` | caret before that char (after the last char of a row when clicked past its end); `shift`-click keeps the anchor |
| `ctrl`+`Z` | `doc.undo` | |
| `ctrl`+`shift`+`Z`, `ctrl`+`Y` | `doc.redo` | |
| `ctrl`+`S` | `doc.save` | |
| scroll on the editor | — | the view scrolls; the document is unchanged |
After any caret movement the view scrolls so that the caret's line is painted. A command the
session refuses changes nothing in the document and shows its kind in `Message`.

### Rust API used by tests
None. All criteria are tested through the built `kiln` binary; `kiln_control::Host` (signatures
as pinned in T-055) is the only Rust API a test may use, as an oracle.

## Pinned
- (a) Errors: no new refusal kinds and no new registry command. A refused command (e.g.
  `doc.save` → `not_found` when the file's directory was removed) leaves the document as the
  session has it and sets `Message` to begin with the kind. Precedence is the commands' own.
  Window start: bad root (exit 2) is checked before the display (exit 2); both before any path
  is opened.
- (b) Files: none beyond T-055's (`--log`); saves only through `doc.save` (ADR-0008 decision 5).
  Source layout, so that the module tasks T-057 to T-061 can run in parallel: the shell places
  each later panel by calling one function in its own file, and this task creates those files
  empty (drawing nothing): `crates/kiln-ui/src/panels/project.rs`, `tabs.rs`, `status.rs`,
  `outline.rs`, `find.rs`. A module task then touches its own file and its own tests only.
- (c) Order: on start, root → display → `<path>` opens in order → first frame. On a key, the
  command is dispatched before the next frame is drawn; the view shows the session's state after
  the command (it re-reads what it shows after any request; never on an idle frame, T-055 S4).
- (d) Offsets in chars, as the commands; rows are document lines (no wrap). Linux, X11 for the
  window (`eframe` with `glow` and `x11`, without `wayland` and without its `accesskit`
  feature: ADR-0008 c4). Fonts built in (monospace for the editor).
- (e) Threat model: the window adds no file access of its own: the files it reads and writes are
  those of commands, confined to the root (`docs/protocol/paths.md`). No process is spawned; no
  network. A document's text is drawn, never interpreted.
- (f) Tests that pin what this changes: T-055's acceptance tests check shell nodes by label and
  value, not the tree's shape, so the added nodes break none (guard file re-runs them). Not to be
  pinned here: the whole snapshot, the usage text, message texts, the layout of panels (T-057
  onward add nodes), the key table beyond the rows above (T-025, T-031 add bindings).
- (g) Worked examples (control parts executed with the `kiln-cli` binary of main `ec08d22`):
  `src/a.rs` = `fn main() {\n    let x = 1;\n}\n` (29 chars); `syntax.highlight {doc:1,start:0,end:11}`
  → `keyword 0..2, plain 2..3, function 3..7, plain 7..11`. So the first painted row is
  `[{"text":"fn","color":"#569cd6"},{"text":" ","color":"#dcdcdc"},{"text":"main","color":"#dcdcaa"},{"text":"() {","color":"#dcdcdc"}]`
  (the row's text `fn main() {` is chars 0..11). A click `at {row:1,col:4}` puts the caret at char
  16 (line 1 starts at 12); `type` `"y"` → `doc.text` `fn main() {\n    ylet x = 1;\n}\n`,
  `cursor.get` head 17 (executed: `cursor.set {anchor:16}`, `doc.insert {offset:16,text:"y"}`,
  `cursor.get` → anchor 17, head 17, line 1, col 5). `Backspace` → the original text, head 16.
  On `a\r\nb` (`doc.info` `line_ending` `crlf`) with the caret at 3, `cursor.move {by:"char",
  forward:false}` gives head 1 (executed), so `Backspace` deletes chars 1..3 (`removed` `"\r\n"`,
  text `ab`, executed). On `x\r\ny` (`crlf`) with the caret at 1, `Enter` inserts `\r\n`:
  text `x\r\n\r\ny` (executed as `doc.insert {offset:1,text:"\r\n"}`). The line ending is read
  when the key is handled: on a text with no break `doc.info` reports `lf` and `Enter` inserts
  `\n`. The implementer re-executes these through the binary.
- (h) Evaluator calls (ADR-0008 (O1)–(O5)):
  - `ui.window`: `kiln script s.jsonl --root d src/a.rs` with a snapshot: `Title` begins with
    `src/a.rs`, `Editor` value equals `doc.text`; plus, as Q-2 decides, `xvfb-run kiln --root d
    src/a.rs --script s.jsonl` with the two libraries of ADR-0008 (d).
  - `ui.editor-view`: snapshots before and after typing, arrows, a click `at`, scroll steps;
    colours against `syntax.highlight` and the table; caret by typing a char and reading
    `doc.text` and `cursor.get`.
  - `ui.dispatch-only`: `--log` of an editing session replayed with `kiln-cli run` on a copy of
    the root gives the same files; frames on an idle editor add nothing to the log.
- (i) Sentences for `docs/protocol/ui-editor.md`, worded for copying, with evidence:
  - E1 "The editor changes a document only by commands: every keystroke that edits, moves the
    caret, undoes, redoes or saves is a request in the session log." Evidence: AC-9.
  - E2 "Enter inserts the document's line ending as `doc.info` reports it when the key is
    pressed." Evidence: AC-6.
  - E3 the colour table above. Evidence: AC-4.
  - E4 "After a caret movement the caret's line is in view." Evidence: AC-7.
  - Limits, copied: "Lines are not wrapped; a long line is cut at the right edge." "The view
    re-reads the document after every request, so the cost of a keystroke grows with the
    document's length; no time bound is stated." (No measurement exists; a bound would need one,
    METHODOLOGY §2.1.)

## Acceptance criteria
Through the built `kiln` binary (`kiln script`, and `kiln` for AC-2), temporary roots, every
process under a timeout; nodes found by label and role.
- AC-1 (`ui.window`): `kiln script s.jsonl --root d src/a.rs` (and, separately, a script that
  opens `src/a.rs` through `Path` and `Open`): a snapshot shows `Title` beginning with
  `src/a.rs`, without `modified`, and `Editor` whose value equals `doc.text` and whose rows'
  texts equal the document's lines from line 0. Oracle: `doc.text`, `doc.line`.
- AC-2 (`ui.window`, start): with `DISPLAY` and `WAYLAND_DISPLAY` removed, `kiln --root d
  src/a.rs` exits 2, stdout empty, stderr one line not containing `panicked`; `kiln --root
  <missing>` exits 2; `kiln --help` exits 0. Oracle: exit codes.
- AC-3 (`ui.window`, real window; run by the reviewer and the evaluator, **not by the gate**,
  because no display exists where the gate runs, ADR-0008 d): under `xvfb-run` with the two
  libraries, `kiln --root d src/a.rs --script s.jsonl` prints for each `snapshot` the same
  `root` as `kiln script s.jsonl --root d src/a.rs` and exits 0. Oracle: equality with headless.
- AC-4 (`ui.editor-view`, colours): for at least 20 Rust files (keywords, types, functions,
  strings, numbers, comments, CRLF and non-ASCII text), every run in the painted rows has the
  table's colour of the `syntax.highlight` kind of each of its chars; a `.txt` document and an
  oversized `.rs` document are painted all `plain`. Oracle: `syntax.highlight` over the rows'
  char ranges and the table.
- AC-5 (`ui.editor-view`, caret): a click `at {row, col}` on `Editor` for random rows and columns
  of the visible text gives `cursor.get` head = the char at that line and column (clamped to the
  line's end); typing a char there inserts it at that offset (`doc.text`); `Editor` `selection`
  equals `cursor.get` after each step; `shift`-click selects from the old anchor. Oracle:
  `cursor.get`, `doc.text`, `doc.line`.
- AC-6 (`ui.editor-view`, keys): random sessions of typed text, `Enter`, `Backspace`, `Delete`,
  arrows with and without `ctrl` and `shift`, `Home`, `End` on LF, CRLF and mixed documents: after
  every step `Editor` value equals `doc.text` and `selection` equals `cursor.get`; the final text
  and selection equal a naive model of the Input table (using the rules of
  `docs/protocol/cursor.md`); in an LF-only and a CRLF-only document, after any session
  `eol.counts` still reports one kind only. Oracle: naive model; `eol.counts`.
- AC-7 (`ui.editor-view`, scrolling): a 300-line document: the first snapshot's rows are lines
  0..k (k ≥ 1); `scroll` `down` n steps on `Editor` makes the first row a later line, rows stay
  consecutive lines, and the document is unchanged; `ArrowDown` from line 0 to line 200 leaves
  line 200 among the rows. Oracle: `doc.line`, `cursor.get`.
- AC-8 (undo, redo, save): after edits, `ctrl+Z`, `ctrl+shift+Z`, `ctrl+Y` give the same
  `doc.text` and `doc.info` (`dirty`, `can_undo`, `can_redo`) as the control requests
  `doc.undo`/`doc.redo` would in a second session given the same edits; `ctrl+S` writes the
  file (its bytes equal `doc.text` in the document's encoding and line endings as `doc.save`
  writes them), and `Title` loses `modified`; a save whose directory was removed leaves the
  document dirty and `Message` beginning with `not_found`. Oracle: a second session
  (differential); file bytes.
- AC-9 (`ui.dispatch-only`): for every session of AC-5, AC-6 and AC-8, running its `--log` with
  `kiln_control::Host` on a copy of the initial root gives the same text for every document and
  the same files; 600 idle frames with a document open add nothing to the log. The `ui-commands`
  gate step passes on the branch. Oracle: replay (differential); log comparison; gate step.
