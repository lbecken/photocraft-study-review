| 3 | defect | `xtask/src/publish.rs:419` (→ `queue.rs:201-217`), steps 2–7 | `publish` takes no queue lock, yet in step 1 it rebuilds the queue's private build tree `<git-common-dir>/kiln-queue/main-xtask/` (removes `src/`, prunes `target/`, deletes the binary) and in steps 2–7 commits three times on main in the primary checkout's index. Run while a queue holds `kiln-queue.lock`, it can delete the binary a running queue is about to run its main gate with (the queue then records `gate-did-not-run`), collide with the queue's own record commit on `.git/index.lock`, and moves main under the queue (`ff_failed main-moved`); it ends with the task `queued`, the inputs removed from the checkout, and the queue's refusal (exit 2). Fix: take `kiln-queue.lock` for the whole publish (refuse in step 1 if it is held) and run step 8's queue under it (in process, or a queue entry point that inherits the lock). The harm to a running queue is by reading (`queue.rs:209-217`); the run without a lock is shown. | toy p4 |
| 4 | defect | `xtask/src/hygiene.rs:366-371` | `session-paths` skips every tracked symlink (`if !meta.is_file() { continue }`). A symlink's content in git is its target path, so a tracked link pointing into a session scratch directory puts the session path in the repository and the check passes. Interface (6): "no file listed by `git ls-files` … contains a match". Fix: for a symlink, check `read_link`'s target text (or scan `git cat-file` blobs of the index). | toy h1 |
