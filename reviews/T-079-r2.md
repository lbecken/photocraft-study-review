## The delta, line by line
- **`DeepChain`** (`acceptance_t019_cli.rs:1555–1589`, used at `:1677`). `take_down` renames `c2100/d` to `c2100-chain`, then
  while that directory has a child `d`: renames the child to `c2100-parent`, `remove_dir`s the emptied level, renames
  `c2100-parent` back; at the end `remove_dir`s the last level. Every call names a short path, none recurses, and no
  descriptor is held across levels. `_chain` is declared after `w`, so it is dropped first. Old and new side by side: the
  build loop, `find d -mindepth 2099 -type d` = 1 line ("the chain is 2,100 deep") and `assert_eq!(l, expected)` are
  byte-for-byte as at `885f4f1`; the delta only adds the `DeepChain` value (`git diff 885f4f1 6dd4cd0` on the test fn).
  - On a normal end a failure of the take-down panics (`expect`), so a take-down that stops early fails the test (N1:
    `DirectoryNotEmpty`), and a take-down skipped on the success path leaves the chain to `Work`'s recursive drop, which aborts
    under 256 KiB (N2) — on Linux's default 2 MiB it passes, so on Linux only the small-stack run sees N2.
  - While the test is already panicking the take-down is best effort and its error is dropped, so it cannot replace or hide
    the real panic: N7 (the `find` assertion made false) prints `panicked at …:1687:5: … the chain is 2,100 deep` and the test
    FAILS normally, without an abort, also under 256 KiB — the take-down succeeds on an intact chain. Two cases remain where
    the chain would reach `Work`'s recursive drop: a panic in the build loop before `_chain` exists (the chain is then
    partial, at most as deep as built), and a take-down that fails part-way while panicking. On macOS either would abort the
    binary after the first panic was printed (nit 3).
- **Twins** (`:1102–1126`). `dot_git_written` is the old literal tree; it is materialized once at `dg-written`, the entries of
  `dg-written/s/t` equal to `z` ignoring ASCII case are counted, and the count must be 1 if `folds_case` says "folds", else
  2; then `dg-written` is removed and `dot_git = as_held_in(dot_git_written, …)` as before. On Linux: 2 = 2. On a folding
  file system, by reading: `materialize` writes in byte order with `fs::write`, so `s/t/Z` is created and `s/t/z` opens and
  overwrites that same file, leaving one entry named `Z`; twins = 1 = expected. No old assertion changed; one added.
- **Scan** (`guard_t079.rs:184–226`). `linux_cfgs` collects `cfg(p)`, and from `cfg_attr(c, a, …)` the cfgs of `a, …`
  (recursively) when `c` holds on Linux or is not known; `kept_on_linux` requires all to hold. Unknown → its cfgs count, so an
  unknown predicate can only remove a name (and an unknown predicate inside the inner `cfg` counts false), never invent one.
  AC-2's `platform_cfgs` now also counts a `cfg_attr` whose applied attributes name a platform (A1: `cfg_attr(test,
  cfg(unix))` on `tree_order_and_counts` fails `ac2_tree_order_and_counts…`).
