# Review T-017 round 1

**Verdict: request-changes.** The one reason is a test gap. The code meets the spec on every
point I could probe. Here is what I checked:
- matches and groups: 25,000 random pairs against my own model, and 30 hand cases;
- expansion: 15,150 templates against my own model of the rule, every Pinned (g) form included;
- the dependency, the lock, the layers and the ruling-s1 cap.

- `find_all` under the cap can use 2.4 GB on a 1 MB text (finding 2);
- the 5 s bound of Pinned (e) for a 100 kB pattern holds only when the text does not match it
  (finding 3).

## Follow-ups
- Finding 2 (result memory under the cap) and finding 3 (time of a 100 kB pattern on a
  matching text): both for the director. They likely belong with the search time and size
  bound planned in T-021/T-022.
- AC-1 run time: `case_insensitive_matches_equal_naive_model` takes 49.5 s in debug and the
  case-sensitive test 10.7 s. They run in parallel, so the acceptance binary takes about 65 s
  wall. That is acceptable for the gate; 20,000 pairs is the spec's minimum, so the pair
  count cannot go down. The cost difference points to the case-insensitive model (fold-set
  lookups, INFERRED). If the gate's time ever matters, speed up the model rather than reduce
  the pairs. Not a finding.
- No test pins an unpinned message: engine messages are always compared with the engine's
  own `Display` at run time. The only literal texts are the cap message (D-060 s1) and
  `no capture group "…"` (Interface). Hard-coded counts are the D-060 cap (100) and the
  engine's nest limit (250). A later change to the cap must update
  `hundred_capture_groups_are_accepted`, `more_than_hundred_capture_groups_are_refused` and
  the unit tests, as intended.
- For T-021 (already in the implementer's log): `expand` maps each reference with an O(text)
  walk (`regex.rs:159–178`), so replace-all is O(text × matches).
