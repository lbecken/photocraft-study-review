## The confinement logic, adversarially (point 2; Windows code read, not run)
- **Every call goes through the walk.** `read`, `write_atomic` (`write_atomic_with` → `locate`), `is_file`,
  `check_location` (`disk.rs:658-660`) and `list_dir` (`Some` → `locate`; `None` → `locate_steps(…, empty)`, i.e. the
  root identity check) all go through it. `project::tree` and `.gitignore` reads use only `Vfs::list_dir`/`read`
  (`project.rs:71, 93, 134, 215`). A `.gitignore` is read only when its kind is `File`, so a reparse `.gitignore` is
  listed `Symlink` and not read. No product file outside `disk.rs` opens a host path (grep for
  `File::open|OpenOptions|read_dir|fs::read`).
- **Last segment, middle segment.** For each `Step::Name` the walk calls `fs::symlink_metadata(dir.join(name))`, and the
  Windows arm comes before the symlink arm, so a reparse point at any component returns `OutsideRoot`
  before `read_link` or descending (`disk.rs:330-337`). `dir` only ever grows by entries just found to be non-reparse
  directories (no link target is pushed on Windows: the symlink arm cannot be reached there, since `is_symlink` requires
  the reparse attribute, `std-win.rs` `FileType::new`). So the OS resolves only checked directories, apart from the
  stated check-to-use window (Pinned (e)). A backslash in a segment, which would let the OS cross an unchecked component
  inside one `join`, is refused lexically (`path.rs:42-43`). `C:x` segments are T-095's (PROBE I1-I3: `OutsideRoot`).
  Short names and case address the entry itself, whose attributes are read, so they give no way around the check
  (INFERRED).
- **Without following?** `fs::symlink_metadata` = `metadata(path, ReparsePoint::Open)`: it opens with
  `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT` and access 0 (`std-win.rs:1500-1549`). If that fails with
  `ERROR_SHARING_VIOLATION`/`ERROR_ACCESS_DENIED`, it falls back to `FindFirstFileExW`, whose cached attributes still
  carry `0x400`. Nothing is followed. In listings, `DirEntry::metadata` is the directory read's own data
  (`std-win.rs:188-190`, `Ok(self.data.into())`), so nothing is opened.
- **Error while reading the attribute.** `NotFound`/`NotADirectory` end the walk as `not_found` (as now). Any other
  error goes to `walk_error`, which is `io_error` while the walk is inside the root, and nothing is followed. That is
  fail-safe. In `list_dir`, an error of `entry.metadata()` fails the whole listing with `io_error`; that cannot happen on
  Windows (infallible there).
- **The root itself; a dangling link; a junction loop.** The root is not on the walk (Interface (1)): `current_root`
  canonicalizes the given path and compares identity. That is T-073's code, unchanged. A dangling link or junction is
  `lstat`-able, so it is refused at its component. A junction loop is refused at its first component (no hop counting
  is reached).
- **An entry at a temporary name.** `create_new(true)` already makes std add `FILE_FLAG_OPEN_REPARSE_POINT`
  (`std-win.rs:329-333`), so the task's `custom_flags(0x0020_0000)` repeats it. That is harmless: the flag is ORed, and
  `create_new` means `CREATE_NEW`, which never opens an existing name. So an existing link, junction, file or directory
  at the name is neither followed nor changed, and its target is neither created nor opened (Win32 documentation, read;
  **unchecked until CI**, Pinned (b2)). The skip arm then calls `fs::symlink_metadata(name)`, and nothing is opened
  beyond the name. All 100 names taken (by `AlreadyExists` or by the arm) → `AlreadyExists` "all 100 temporary file
  names are taken" (`disk.rs:489-492`), as specified. A failure with nothing at the name → the create's own error.
  Window: an entry appearing between create and look skips one name; one vanishing returns the create's error. Both
  are harmless.
- **Cannot be decided without a Windows run:** that `CREATE_NEW` + open-reparse on an existing *file* link answers
  `ERROR_FILE_EXISTS` and on a junction `ERROR_ACCESS_DENIED` (H2 is consistent with the junction; which entry refused
  is not determinable); that `mklink /D` and a dangling `mklink /J` work on the runner, and links on `C:` (F-12); a
  directory symbolic link as `--root`; the removed-then-junction case; that every reparse tag the runner can make
  carries `0x400` in `symlink_metadata` (PROBE B1 shows six); the `..` rule on macOS.
