is correct. Every refusal site carries the reason the spec assigns, no message changed, the

(mutant M11 survives the whole suite and the gate).

### Director duties
1. **Contract change.** Every refusal site carries the reason the spec assigns. I compared every
   `rejected(`/`Internal {` construction in non-test code with the spec's source list. There are
   9 `Rejected` sites (doc.rs ×7, buffer.rs ×1, registry.rs `no_such_doc` ×1) and 3 `Internal`
   sites (registry.rs:499, :556; kiln-control lib.rs:133). No other module constructs a
   `CommandError` refusal, and there is no `impl From<…> for CommandError`.
   - Messages: every format string in the diff is byte-identical to base.
   - Guard coverage: `guard_t032` pins messages from all 9 `Rejected` sites. `doc.open` is
     covered for invalid / not-found / directory / decode, and `doc.delete` through the inverted
     case. No site is missed.
   - `to_json`: still the serde derive, so `reason` appears only on `Rejected`/`Internal`. M8
     (reason added to request-level errors) is killed by
     `guard_t032::request_level_errors_keep_their_json`.
2. **Protocol bytes.** `protocol_bytes_are_unchanged` is real differential evidence for the
   scripts it runs. Its constants are said to be recorded on base, and the join ran the guard on
   base and on the join with 0 failures in both. So base output equals the embedded constants,
   which equal the join output. That covers the worked example (run and control), 12 `exec`
   cases incl. Pinned (g), and the 320-request session via run, control and replay.
   - Kinds exercised: `invalid_path`, `no_such_document`, `unsaved_changes`, `not_found`,
     `decode_error`, `out_of_range`, `inverted_range`, and the request-level kinds.
   - Not exercised: `not_a_file` (excluded by D-043), `io_error` and all `internal` kinds. For
     those, base's `rejected_kind` (removed lines of kiln-control lib.rs) gives the same kind for
     every message without `": "` inside the path. I checked this by reading, not with a base
     binary.
   - So the guard replaces the implementer's missing byte-for-byte comparison for the covered
     kinds only. For `io_error` and `not_a_file`, the evidence is reading plus my CLI probes on
     the join (no base build was made: disk).
3. **Generated list.** `error_kinds` comes from `RejectReason::ALL`/`InternalReason::ALL` through
   `describe()`. The gate's `schema` step compares the dump byte for byte (M10/M15/M16 were
   regenerated with `cargo xtask schema --write`, and the acceptance tests still killed them).
   The two sentences match the spec text exactly (AC-7).
4. **Closure for dependents.** It is only partly closed.
   - Closed:
     - a new lower-layer variant cannot compile until it is mapped (no catch-all);
     - a new reason variant cannot compile until `as_str` and `description` have arms;
     - kiln-control needs no change (M9/M13 show a message-based fallback is caught).
   - Not closed: `ALL`. A variant added without its `ALL` entry passes every test, the gate's
     `schema` step and `commands --schema` (M11, finding 1). Its kind would then be produced by
     the protocol while missing from `error_kinds`, which `docs/control-protocol.md` now calls
     the specified set. The same holds for `InternalReason::ALL`.
5. **Revert-check.** `mixed`, 5/5 targets fail with the implementation reverted (above).
6. **Mutation spot-check.** 16 introduced: 13 killed by acceptance, 1 killed by a guard only (M8)
   and 2 survived (M11, M12). The working tree was clean after each (`git status --short`
   empty).
