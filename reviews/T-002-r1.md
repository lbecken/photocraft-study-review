## Data-loss probes (summary)
- **Interrupt safety** (reasoned from `disk.rs:118-192`). The sequence is: open temp
  (create + truncate), write, fchmod, fsync, rename, then a best-effort fsync of the directory.
  A crash before the rename leaves the target intact and a leftover temp. A crash after it
  leaves either the old or the new directory entry, both complete because the data was synced.
  This is sound, apart from D-3 (permissions are applied after the data) and the leftover
  handling (D-1, TG-1).
- **Read-only target** (P1, as `nobody`, file 0444, directory writable): `Ok(7)`, content
  replaced, mode stays 0444, document clean. See SG-2.
- **Directory not writable** (P2, as `nobody`): `Err(Io{PermissionDenied})`, file unchanged,
  document still dirty, no leftover. Correct.
- **Can a failed save leave the document clean?** No. `saved_text` is assigned only after
  `write_atomic` returns `Ok` (`document.rs:101-102`), and M13 confirms a test guards this. The
  only error swallowed is the directory fsync, after the rename has happened (`disk.rs:132-136`),
  which is acceptable.

| D-1 | defect | `crates/kiln-workspace/src/disk.rs:119-123,176-182` | The temp file is opened with `create+truncate`, which follows symlinks and accepts an existing file. If `.<name>.kiln-tmp` is a symlink, save writes the document into the symlink's target (any file, even outside the root), then renames the *symlink* over the target, so the target becomes a symlink. This is data loss on an unrelated file and a classic predictable-temp-name hazard. Fix direction: create the temp with `create_new` (O_EXCL) and, on Unix, `O_NOFOLLOW`. If the name exists, either unlink it (unlink does not follow links) and retry, or move to a deterministic alternate name (see SG-1). | P4: victim outside root `"precious"` → `"oldEDIT"`; `f_is_symlink=true`; `save` returned `Ok(7)` |
| D-2 | defect | `disk.rs:173-176` | The temp name `.<name>.kiln-tmp` adds 10 bytes, so any file whose name is 246–255 bytes long opens and edits but can never be saved (ENAMETOOLONG on every attempt).
