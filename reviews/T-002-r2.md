## Implementer's two questions
- **A new file's mode follows the umask.** This is acceptable behaviour. During the write the
  temp is never more readable than the file that results, so nothing leaks that the final file
  would not show. But D-014 (2) literally says "created owner-only" without condition, so this
  is SG-8. The behaviour is tested by unit test `new_file_gets_default_mode`; no acceptance test
  covers it.
- **`AlreadyExists` when all 100 names are taken.** This is acceptable. Ruling (1) forbids
  touching foreign files, so refusing is the only compliant outcome. It is tested by unit test
  `all_temp_names_taken_fails_without_changes_then_recovers`, which checks that the listing,
  target and decoys are unchanged and that a save succeeds after one name is freed. Probe Q6:
  the document stays dirty and `f` stays `"old"`. No acceptance test covers it; the test author
  does not know the scheme, so this is fine. The message does not tell the user what to clean
  up (N-5).
