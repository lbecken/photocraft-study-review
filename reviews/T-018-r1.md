## Implementer's departures
- **`Buffer::line_break_count` (new public).** Acceptable, but it is a spec gap (finding 5).
  `eol.counts` needs per-kind counts, and the Interface gave no way to read them without scanning
  the text. The method reads the existing incremental `BreakCounts` (`buffer.rs:394`).
- **`Buffer::moved` clamps an invalid `from`.** Acceptable. The spec does not say what happens
  for an invalid `from`. The behaviour is documented on the method (`buffer.rs:446-449`) and
  unit-tested (`moved_clamps_invalid_from`). `cursor.move` only ever passes the head, which is
  always valid.
- **`head: null` / `to: null` accepted as absent.** This is a spec gap (finding 4), and it made
  one doc sentence false (finding 1, a defect). The generated schema documents it
  (`"type": ["integer","null"]`, and `anyOf [Target, null]`). But `extend: null` is refused
  (`invalid_params`), so the three optional params are inconsistent, and `eol.md:55` says the
  opposite.

## Revert check
`cargo xtask join --revert-check T-018`, run from the primary checkout at 2026-11-13T17:15:20Z.
It reverted the 7 non-test commits:

`metrics/tasks.jsonl` in the primary checkout and left uncommitted.

**The record again counts only 6 tests, and I found why: it is an xtask defect outside this
task.** `acceptance_targets` (`xtask/src/join.rs:68-92`) collects target names as file stems in
a `BTreeSet<String>`. `CargoOracle::acceptance` (`join.rs:95-117`) then looks up one binary per
stem with `find(|b| b.kind == "test" && &b.target == target)`. `crates/kiln-text/tests/acceptance_t018.rs`
and `apps/kiln-cli/tests/acceptance_t018.rs` have the same stem, so they collapse into one entry.
Only the first compiled binary of that name is run. With the implementation reverted, the
kiln-text target does not compile, so the binary found is kiln-cli's. The kiln-text target
appears neither in `results` nor in `not_compiled`.

The same collapse explains why the join record lacks the kiln-text tests. Any two crates with
an `acceptance_tNNN` target of the same name hit it. So for the kiln-text target, the evidence
that the tests can fail is the mutation table above (13 mutants killed by it), plus the fact
that it does not compile on the base. The revert check gives no such evidence. This needs a
director decision; see Follow-ups.
