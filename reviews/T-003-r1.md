## Specific questions from the director
1. **Commands through `kiln-cli exec`.** All eleven are dispatched, validated and answered with
   structured errors, and nothing panics. Because `exec` builds `Context::with_text(text)`, an
   empty MemoryFs, for each invocation, only `doc.list` (→ `{"docs":[]}`) can succeed. The other
   ten can only fail with `rejected` (`cannot open a.txt: not found`, `no open document 1`). No
   example can be reproduced through `exec`; they are reproduced only through `commands --audit`.
   → SG-1.
2. **D-020 applied narrowly:** yes for `main.rs`. However, the same brittle exact-list assertion
   in `crates/kiln-commands/src/buffer.rs` `standard_registry_passes_its_own_audit` was loosened
   in `6323bf3`, from `names() == [buffer.insert, buffer.text]` to "the `buffer.`-prefixed
   names are those two". This file is inside `touches`, so no ruling was needed, but the
   implementer's log does not mention it. The doc names stay covered by
   `describe_lists_doc_commands_with_mutating_flag` and the acceptance registry tests. → N-1.
3. **Tests in `src/` instead of `tests/`:** nothing is lost, and something is gained. The unit
   tests use only public items (`crate::{CommandError, Context, LogEntry, Registry,
   standard_registry}` and the public `MemoryFs::set_fail_writes`), so they would compile
   unchanged under `tests/`. They run in the gate. They are the only killers of M21, M28 and
   M29. What is lost is minor: they cannot be named in a scorecard item (by design only
   acceptance tests are), and `doc.rs` is 1324 lines, about 570 of them tests (N-5).
4. **`docs/commands.json`:** equals `kiln-cli commands --schema` and `cargo xtask schema`
   passes. Thirteen commands each have a `mutating` flag; doc examples have non-empty `files`
   and `setup`, and buffer examples have empty ones. The audit runs each example, setup
   included, and compares the exact result (green). The audit compares only the result, not
   the files afterwards: an example `doc.save` that did not write would pass the audit. M1
   shows that the acceptance tests catch it.
5. **Logging and replaying read-only commands:** as implemented, this does not make replay
   diverge. The four read-only commands only read state (`doc.rs` `Text::run`, `Info::run`,
   `List::run`; `buffer.rs` `Text`), and logging them is reproduced exactly on replay
   (idempotence holds; M12 is killed). Three real risks remain:
   (a) `mutating:false` is a claim nothing enforces (`run` takes `&mut Context`). A read-only
   command with a side effect (M28/M29) passes the whole acceptance suite, including the replay
   round-trip, because replay reproduces the side effect too. It would diverge only for a
   consumer that skips `mutating:false` entries. → SG-3.
   (b) Replay does not check results. The log stores no results, so replay on a different
   initial state returns `Ok` with different results (probe: `a.txt`="one" vs "two" → both
   `Ok`, `doc.text` differs). → SG-2.
   (c) Replay ignores the logged `mutating` field. A tampered entry
   (`doc.list`, `mutating:true`) replays, and the new log says `false`. → SG-2.
6. **Test author's `QUESTION:` lines:** ruled as SG-4, SG-5 and SG-6, with recommended answers
   below. The R-022 log entry is complete in the task file; only the final chat report was lost
   (D-022).
