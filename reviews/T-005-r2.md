### The director's two readings
- *Gate paths include `xtask/tests` and config files at any depth.* No ordinary task is made
  unmergeable. `xtask/tests` only affects xtask tasks, which are tier high anyway. Config files at
  any depth (`build.rs`, `clippy.toml`, `rustfmt.toml`, `rust-toolchain*`, any `.cargo/` segment),
  together with the R4 rule for nested `Cargo.toml` dependency tables, escalate a product task that
  commits a *fixture project* — plausible for an editor of Rust code (workspace loading, formatting,
  build-script handling) — to tier high plus a `gate paths` approval. That is a cost, not a block.
  The one real block is a nested fixture `Cargo.lock` whose versions change (F13).
- *`ledger` covers all of `metrics/` except `queue.jsonl`.* No block for an ordinary task: `join`
  leaves `metrics/tasks.jsonl` uncommitted, so the director must commit it before queueing (the
  refusal says so), and `queue.jsonl` may stay uncommitted. The exemption is what keeps F15 open.

### Residual risks after this round (plainly)
1. **Cached dependency artifacts** (accepted): gated task code can overwrite a dependency's
   `.rlib` in `kiln-queue/main-xtask/target` and future-date it; main's xtask is then rebuilt
   linking it. That gives the same capability F1 had, by deliberate action only. The threat model
   (D-026) excludes a malicious agent, and the accident case is closed.
2. Gated task code still runs as the director's user and can write anything — the primary
   checkout's working-copy `queue.jsonl` (F15), `.git`, other worktrees. The queue protects
   against shortcuts, not against hostile code.
3. Member `[lints]`, custom build-script paths and `members`/`exclude` changes (F11) are silent
   gate weakenings.
4. After `reviewed_sha` the task's own acceptance/guard files may change (D-027 R2) with neither
   re-join nor re-review: a weakened acceptance test after review reaches main unseen
   (`precheck.rs:270-278`; methodology §6 "implementer never edits acceptance_t*" is still unchecked).
5. The approval row is still not bound to a sha or round (D-2). Review authorship (`Role:`), the
   `findings`/verdict consistency and tier-vs-`touches` beyond gate paths/dependencies remain
   director checks.
