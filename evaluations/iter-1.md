### NEW-1 — already-open path skips confinement and root checks
- Reproduction A (`drivers/paths2.py`, step S12): in `kiln-cli control --root pc2/root`,
  `doc.open {"path":"reopen.txt"}` → doc 11; `doc.insert` `EDIT `; then outside Kiln
  `rm reopen.txt; ln -s ../out/secret.txt reopen.txt`; `doc.open {"path":"reopen.txt"}` →
  `{"id":34,"ok":true,"result":{"already_open":true,"doc":11,…,"path":"reopen.txt"}}`.
  A path that is not already open and leads outside the same way (`rel_out` → `../out/secret.txt`,
  `paths.py`) is refused `outside_root`.
- Reproduction B (`drivers/rootid.py`, A, B, C, D, and the `rr` run): after the root was renamed
  and replaced (or re-pointed, or removed, or replaced by a link to an outside directory),
  `doc.open {"path":"a.txt"}` (open before) → `{"ok":true,"result":{"already_open":true,…}}`,
  while `doc.open {"path":"b.txt"}` and `doc.save` in the same state → `outside_root`.
- Expected: paths.md "The rule": "At open and at save (and whenever Kiln checks whether a file
  exists): **A path whose location is outside the root is refused** as `rejected` /
  `outside_root`"; and "The root": "the session refuses every path with `outside_root`, at open
  and at save, including the save of a document opened before". `doc.open`'s own description
  ("Opening a path that is already open returns the existing document unchanged") does not
  say it is exempt.
- Impact: nothing on disk is read or written (text is the in-memory buffer; the later save is
  refused), so the confinement of disk access holds. Either the check is applied to the
  already-open case, or paths.md must say that re-opening an open path is not checked.

### NEW-2 — `error_kinds` publishes kinds that cannot occur
- Reproduction: `kiln-cli commands --schema | python3 -c 'import json,sys;
  print([k["kind"] for k in json.load(sys.stdin)["error_kinds"]["rejected"]])'` lists, after the
  10 iteration-0 kinds, `invalid_pattern, stale_preview, no_such_preview, tool_unavailable,
  tool_not_found, tool_timeout, tool_failed, no_recording, format_error, changed_on_disk,
  invalid_keymap, not_a_boundary, outside_root`. `kiln-cli commands` lists 20 commands
  (`buffer.*`, `cursor.*`, `doc.*`, `eol.*`); none searches, previews, runs a tool, formats,
  checks for external changes or reads a keymap. None of those 11 kinds appeared in any response
  I looked at in this evaluation; I did not count the responses.
- Expected: control-protocol.md: "the `rejected`/`internal` kinds in `error_kinds` of
  `docs/commands.json` … are the specified set; no other pair is produced". A client reading the
  specified set is told about refusals of features (`tool_unavailable`: "external tools are off
  for this session (the default)") that do not exist; `changed_on_disk` in particular suggests
  external-change detection (`io.external-change` is `planned`; iteration 0 showed silent
  overwrite).
- Suggested: publish only kinds some registered command can produce, or mark the reserved ones.

### NEW-3 — `not_a_file` description wider than behaviour
- Reproduction: `kiln-cli exec doc.open '{"path":"f.txt/x"}' --root pc/root` (f.txt is a regular
  file) → `{"code":"rejected","kind":"not_found","message":"cannot open f.txt/x: not found"}` rc
  2; save after the parent directory `sub2` was replaced by a regular file (`paths2.py` S6) →
  `{"code":"rejected","kind":"not_found","message":"cannot save sub2/x.txt: not found"}`;
  `--memory-seed` with `a.txt`, `doc.open a.txt/x` → `not_found` too.
- Expected: `error_kinds` `not_a_file`: "the path names a directory or another non-regular file
  where a file is needed, **or a file where a directory is needed**"; control-protocol.md:
  "Where a row's 'When' text differs from `error_kinds`, `error_kinds` governs". paths.md ("If a
  component before the last does not exist or is not a directory, the walk stops there"; a file
  reached through a trailing-`/` link is `not_found`) agrees with the binary, so the two
  documents disagree and the governing one is the wrong one.
- Related (already acknowledged in doc-positions.md, not filed separately): `out_of_range`'s
  `when` "an offset beyond the end of the text" is narrower than its use for lines and columns.

### NEW-4 — control-protocol.md CLI section is stale for `--memory-seed`
- Reproduction: `kiln-cli --help` shows `run <script> [--root <dir> | --memory | --memory-seed
  <manifest>]` and the same for `exec`; `kiln-cli run s.jsonl --memory-seed m2.json` → exit 2
  `kiln-cli: bad --memory-seed m2.json: key `files` repeated in one object`.
- Expected/found: control-protocol.md "`kiln-cli`" synopsis lists `run <script> [--root <dir> |
  --memory] [--log <file>]` and `exec … [--root <dir> | --memory]`; "`--memory` … cannot be
  combined with `--root`" (it also cannot be combined with `--memory-seed`); the exit-code table's
  exit 2 lists no bad manifest. cli-memory-seed.md covers the option and says it adds an exit-2
  case, so this is narrower wording in the main protocol document, not wrong behaviour.

## Questions for the director
- **Q1 (undo.grouping):** a `doc.redo` with nothing to redo (`redone:false`) leaves the typing
  group open: insert `a` at 10, `doc.redo`, insert `b` at 11, one `doc.undo` removes both. No
  document says what a no-op redo does to the group (a no-op `eol.normalize` is documented to
  leave it open; `cursor.set`/`cursor.move` close it even when nothing moves). Intended?
- **Q2 (edit.selection):** the selection is kept and mapped through every edit, but no command
  other than `cursor.*` reads it (`doc.insert` takes an explicit offset; it is not in `doc.info`;
  it is not saved). It is observable only through `cursor.get`. Is a consumer planned (typing at
  the caret, deleting the selection), or is this enough for the item?
- **Q3 (text.positions):** `byte` is the UTF-8 offset in the decoded text, not in the file:
  in `bom.txt` (UTF-8 with BOM) `char 2` → `byte 2` (the file offset is 5); in a UTF-16 LE file
  `char 3` → `byte 7` (UTF-8 count). doc-positions.md says "a UTF-8 byte offset", so this matches
  the text, but tools that report file byte offsets (planned `diag.positions`) would need a
  BOM/encoding adjustment. Intended?
- **Q4 (messages):** small inconsistencies in human-readable text, not filed because messages are
  documented as not stable: `doc.insert` says `char index 7 is out of bounds (buffer has 6
  chars)` while `doc.position` and `cursor.set` say `index 7 is out of bounds (length 6)`;
  `column … for line 0 (1 chars)` (plural for 1). Worth a task or leave?
